# 섹터/분류 분리 — 컨텍스트 노트

## 왜 나눴나
`sector` 한 필드에 자산군(ETF/주식, 예적금)과 산업(반도체, 통신)이 섞여 있었다.
성격이 다른 두 축이라 하나로 묶으면 어느 쪽으로도 제대로 집계되지 않는다. 그래서 나눈다.

- **섹터** = 자산군. 국내ETF/해외ETF/국내주식/해외주식/펀드/채권/현금성
- **분류** = 산업/테마. 지수형/반도체/AI인프라/2차전지/테크/조선/우주/금융지주/통신/바이오

## 결정과 이유

**필드명은 `classification`.** `category` 는 이미 계좌 분류(ISA/연금저축펀드/…)가 쓰고 있어
충돌한다. `theme` 도 후보였지만 UI 라벨이 "분류"라 그대로 옮겼다.

**레거시 값은 읽을 때 변환하지 않고 스타트업에서 1회 정규화한다.**
읽기 시점 변환은 통합자산 조회와 수동자산 목록 두 군데에 흩어지고, 저장 경로와 어긋난다.
main.py 에 이미 ALTER TABLE 스타트업 마이그레이션 선례가 있어 같은 자리에 붙였다.
매핑 키가 전부 구 목록 값이고 신 목록과 겹치지 않아 재실행해도 안전하다(멱등).

**KIS 종목 섹터는 추론값을 기본으로 준다.**
보유 종목이 57개라 전부 수동 지정은 부담이다. 이름에 ETF 브랜드 토큰(KODEX/TIGER/SOL/…)이
있으면 ETF, 없으면 주식으로 보고 기존 국내/해외 휴리스틱과 조합해 4개 중 하나를 넣는다.
어디까지나 기본값이고 사용자가 드롭다운으로 덮어쓰면 오버라이드 테이블이 이긴다.

**분류 기본값은 빈 값("미지정")이다.** 산업 테마는 이름만으로 추론이 위험하다.
빈 값은 드롭다운에서 "— 미지정 —" 으로 고를 수 있게 두어 되돌릴 수 있게 했다.

**PATCH 경로는 `/holdings/{id}/sector` 를 유지한다.**
섹터와 분류를 함께 받도록 페이로드만 확장했다. 경로까지 바꾸면 프런트/테스트 churn 만 커진다.

## 발산형 바
0% 를 트랙 왼쪽 끝이 아니라 전체 +/− 범위에 비례한 지점에 둔다.
`zeroPct = maxNeg / (maxPos + maxNeg) * 100`.
전부 양수면 zeroPct=0 이라 기존 모양과 같고, 전부 음수면 zeroPct=100 이 되어 왼쪽으로 자란다.
따라서 "+− 혼재일 때만" 이라는 조건을 따로 분기할 필요가 없다.

수익률 텍스트는 트랙 안에서 빼내 오른쪽 별도 컬럼으로 옮겼다.
발산형에서는 바 끝 위치가 제각각이라 트랙 안에 두면 0선과 겹친다.
