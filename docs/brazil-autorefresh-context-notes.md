# 브라질채권 탭 자동 갱신 컨텍스트 노트 (2026-10-05)

## 문제
사용자가 탭을 열었을 때 뉴스·AI 분석·이벤트가 옛 내용이라 수동 갱신 버튼을 눌러야 했다. 진입 시 자동 동작은 이랬다.
- AI 전략 리포트: 날짜가 바뀌었을 때만 재생성(같은 날은 몇 시간이 지나도 그대로).
- 대선 정세 Live Pulse: GET이 날짜 기준으로만 생성, 프론트 자동 재생성 없음.
- 대선 인텔리전스 팝업: `auto_refresh=false`로 저장본만 조회.
- 이벤트 캘린더: 지난 이벤트의 발표값이 비어 있을 때만 동기화.
- 뉴스: 서버가 20분 TTL로 재수집하지만 프론트는 서버 수집 시각을 몰라 "갱신" 표시가 조회 시각이었다.

## 결정
- 기준: 각 콘텐츠의 서버 기준 시각(generated_at·synced_at)이 1시간보다 오래면 수동 버튼과 같은 함수를 자동 호출한다.
  시점은 탭 진입(마운트), 창 복귀(visibilitychange), 열려 있는 동안 5분 폴링.
- 자동 갱신은 스피너만 보이고 토스트·alert는 띄우지 않는다. 실패하면 같은 항목은 10분 뒤에 다시 시도한다(무한 재호출 방지).
- 이벤트 캘린더 수동 버튼은 `force=true`로 지난 이벤트 전부를 Gemini로 다시 쓰고 수동 편집도 덮는다. 1시간마다 이렇게 하면
  호출이 많고 오래된 이벤트 문구가 매번 바뀐다. 자동 갱신은 `recent_days=7`로 최근 7일 이벤트만 강제 재분석하고 수동 편집본은 보존한다.
  수동 버튼 동작은 그대로 둔다.
- 대선 인텔리전스 자동 갱신은 서버 규칙(수동 편집 후 24시간 AI 덮어쓰기 금지)을 프론트에서도 지킨다.
- Gemini 호출량: 누군가 탭을 보고 있을 때 시간당 최대 리포트 1 + Pulse 1 + 캘린더 최근 이벤트 몇 건 + (팝업을 열면) 인텔리전스 1.
- 이벤트 동기화 시각은 `SectorInsight('brazil_catalysts').generated_at`을 쓴다. 동기화는 항상 저장하므로 마지막 동기화 시각과 같다.
  다만 /summary의 지난 이벤트 기본값 자동 반영도 같은 행을 저장하므로 그 직후 1시간은 동기화가 미뤄질 수 있다(영향 작음).
