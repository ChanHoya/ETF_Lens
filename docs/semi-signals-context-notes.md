# 반도체 7대 실데이터 신호 — 컨텍스트 노트

## 왜 손대는가

`e675354f` 커밋이 "더미→실데이터 교체"를 했지만 실제로 실데이터로 바뀐 건 `series_*`
배열뿐이었다. 헤더 수치(`current_value`), 52주 고점, YoY 배지, status, description 안의
숫자는 전부 상수로 남아 있어서 같은 카드 안에서 차트와 헤더가 서로 다른 값을 말했다.

브라우저 실측으로 확인한 불일치.

| 항목 | 화면 표시 | 실데이터 계산값 |
|---|---|---|
| 대장주 낙폭 | −20.3%, 52주 고점 $157.50 | −14.7%, 52주 고점 $1,133.82 |
| 업종 지수 | −19.8% | −18.1% |
| 실질 수출물량 | 213.6 | 59.6 (차트 마지막 값) |
| 수출액 YoY | +52.4% | +2.5% |
| 단가지수 YoY | +183.1% | +0.9% |

## 결정과 이유

### 1. 주가 시계열은 "주간"이다 — 슬라이스 상수를 주 단위로

`_fetch_real_daily()`가 이름과 달리 `resample("W-FRI")`로 주간 리샘플링해 522포인트를
만든다. 그런데 백엔드는 `[-1250:]`, 프런트는 `길이 > 300 → 일별`로 보고 250/750/1250/2500을
잘랐다. 522개 배열에서 750/1250/2500은 전부 전체를 반환하므로 3년·5년·10년 버튼이 완전히
같은 차트를 그렸다. 1년 버튼만 250개(≈4.8년)를 잘라 라벨과 어긋났다.

- 함수명을 `_fetch_real_weekly`로 바꿔 실제 동작과 일치시킴.
- 주간 슬라이스 상수 52/156/260/520 적용.
- 프런트는 날짜 문자열 길이(`YYYY-MM`=7 → 월간, `YYYY-MM-DD`=10 → 주간)로 주기를 판별.
  포인트 개수 휴리스틱은 데이터가 늘거나 줄면 다시 깨진다.

### 2. 낙폭 지표의 차트는 낙폭(%)으로

헤더가 `-20.3%`인데 차트 Y축은 0~1200(주가 $)이었다. 지표 이름이 "대장주 낙폭"이고
description도 낙폭을 설명하므로, 차트를 직전 52주 고점 대비 낙폭(%) 시계열로 바꿨다.
주가 정보가 사라지지 않도록 현재가와 52주 고점은 `sub_name`에 남긴다.

### 3. status 임계선

실측값에서 호황/중립/둔화를 판정한다. 임계선은 아래로 고정하고 description에 명시한다.

| 지표 | 기준 | 호황 | 둔화 |
|---|---|---|---|
| 대장주 낙폭 | 52주 고점 대비 낙폭 | ≥ −10% | < −25% |
| 업종 지수 | 52주 고점 대비 낙폭 | ≥ −10% | < −25% |
| 한국 수출액 | YoY | ≥ +15% | < −5% |
| 수출 단가지수 | YoY | ≥ +10% | < −5% |
| 실질 수출물량 | YoY | ≥ +10% | < −5% |
| 가동률지수 | 지수 레벨 | ≥ 105 | < 95 |
| 재고지수 | YoY (낮을수록 호황) | ≤ −5% | > +10% |

재고지수만 레벨이 아니라 방향(YoY)으로 판정한다. 재고는 절대 수준보다 소진 중인지가
사이클 신호이기 때문이다.

### 4. `signals_count`는 반도체만 실측 집계

`signals` 배열은 업종과 무관하게 항상 반도체 데이터다(기존 구조). 그래서 조선·화장품 등을
선택해도 아래 목록은 반도체 7개 지표가 그대로 나온다. 이건 이번 범위 밖의 기존 한계라
건드리지 않았고, 대신 **반도체일 때만** 좌측 카드의 "호황 N · 중립 N · 둔화 N"을 실제 판정
결과에서 집계해 목록과 카드가 서로 다른 말을 하지 않게 했다. 다른 업종은 기존 메타값 유지.

`weighted_score`·`score_gauge_pct`·`current_state`는 업종별 서술형 메타로 남겨뒀다. 이번
수정 범위(지표 헤더 정합성)를 벗어나고, 국면 판정 로직 자체를 실데이터로 재설계하는 건
별도 작업이다.

> 이 절의 결론은 아래 "2차"에서 대체됐다. `industry_meta_map`은 제거됐고 국면·점수·게이지·
> 타임라인 전부 실측 판정으로 바뀌었으며, 업종별 지표도 분리됐다.

### 5. 실질 수출물량 산식 통일

헤더 213.6은 출처 불명 상수였고, 시계열의 마지막 값은 59.6이다. `HISTORICAL_MACRO_SERIES`의
`volume`은 `export_amt / unit_price × 100`과 일치하므로(144.5 / 242.3 × 100 = 59.6) 시계열
쪽이 내부 정합적이다. 헤더를 시계열 마지막 값으로 맞췄다.

## 배포 주의

`dashboard/.env.local`이 `NEXT_PUBLIC_API_URL=https://etf-lens.onrender.com`을 고정하고 있어
`npm run dev`도 배포 백엔드를 본다. 로컬 백엔드로 검증하려면 셸 환경변수로 덮어쓴다.

```
NEXT_PUBLIC_API_URL=http://localhost:8000 npm run dev
```

셸 환경변수가 `.env.local`보다 우선한다. 이 수정은 백엔드 변경이므로 Render 재배포 전까지는
운영 화면에 반영되지 않는다.

# 2차 — 국면 판정 실데이터화 + 업종별 실데이터 분리

## 무엇이 상수였나

1차 수정 후에도 좌측 카드는 전부 서술형 상수였다. `industry_meta_map`에 업종별로
`state`(정상 호황), `score`(+0.40), `gauge`(70), `transition`, `comment`가 박혀 있었고
13개월 타임라인도 `timeline_months` 리터럴이었다. 지표 7개만 실측이고 그 지표들이 만드는
결론은 손으로 쓴 값이었다.

게다가 `signals` 배열은 업종과 무관하게 항상 반도체 데이터였다. 조선을 눌러도 "한국 수출액
144.5억$"(반도체 수출액)이 그대로 나왔다.

## 판정 엔진 설계

### 지표 → 점수 → 국면

각 지표를 임계선 기준으로 [-1, +1]로 정규화하고(`_score_metric`), 가중 합산한 뒤
5국면에 매핑한다(`_phase_of`). 가중치는 선행성 순서다.

| 지표 | 가중치 | 판정 기준 |
|---|---|---|
| 대장주 낙폭 | 0.20 | 52주 고점 대비 낙폭 |
| 업종 지수 | 0.15 | 52주 고점 대비 낙폭 |
| 한국 수출액 | 0.20 | YoY |
| 수출 단가지수 | 0.15 | YoY |
| 실질 수출물량 | 0.10 | YoY |
| 가동률지수 | 0.10 | 지수 레벨 |
| 재고지수 | 0.10 | YoY (역방향) |

국면 경계는 종합 점수 기준으로 0.50 / 0.15 / −0.15 / −0.50이다. 값이 없는 지표는 빼고
남은 가중치로 재정규화하므로, 지표가 2개뿐인 업종도 같은 척도로 판정된다.

### 배지 밴드와 점수 밴드를 분리한 이유

낙폭 지표의 배지(호황/중립/둔화)는 −10% / −25%를 쓴다. 설명 문구와 같은 기준이라야
사용자가 읽고 검증할 수 있다. 그런데 이 좁은 밴드를 국면 점수에 그대로 쓰면 낙폭이
−25%만 넘어도 −1로 포화돼, 시세 지표만 있는 업종의 국면이 매달 강한호황↔심각불황으로
뒤집혔다(실제로 첫 구현에서 그렇게 나왔다). 그래서 국면 점수용 밴드는 0 ~ −40%로 넓게
잡아 기울기를 살렸다.

### 3개월 평활

월별 원점수를 구한 뒤 3개월 이동평균을 취해 타임라인과 현재 국면을 만든다. 사이클 국면이
주가 한두 주 움직임으로 뒤집히면 국면이라고 부를 수 없다. 평활 전 반도체 타임라인은
`26-06 호황둔화 → 26-07 불황입구 → 26-08 호황둔화`로 튀었고, 평활 후에는
`정상호황 → 호황둔화 → 호황둔화`로 정리됐다.

### 전환 문구와 방향

`state_transition`은 타임라인에서 유도한다. 현재와 다른 가장 최근 국면을 찾아 "직전 국면 X
(N개월 전) ➔ 현재 Y"로 쓰고, 방향은 3개월 전 점수와의 차이로 정한다(±0.05 이내면 횡보).

## 업종별 실데이터

`INDUSTRY_PROFILES`에 업종마다 대장주 티커와 업종 지수 정의를 둔다. 반도체는 SOX라는 공식
지수가 있지만 국내 업종은 없어서, 대표주 2~3종목의 **동일가중 바스켓 지수**(시작=100)를
직접 산출한다. 공식 지수가 아니라는 점이 드러나도록 이름을 "○○ 대표주 동일가중 지수"로
쓰고 구성 티커를 `source`에 명시했다.

티커는 전부 yfinance에서 10년 주간 종가가 실제로 나오는지 확인하고 골랐다. 상장이 늦은
종목(LG에너지솔루션 2022~, 에코프로비엠 2019~, HD현대중공업 2021~)은 10년 시계열이 끊겨
바스켓 시작점을 끌어올리므로 제외했다.

시세는 `yf.download`로 여러 티커를 한 번에 받는다(11개 업종 28티커 ≈ 1초). 업종 요약
엔드포인트가 11개 업종을 각각 판정해야 해서 개별 호출로는 감당이 안 된다.

## 공표통계 미연동 업종 처리

수출액·단가·물량·가동률·재고는 관세청/ECOS/KOSIS 공표통계이고 현재 반도체 120개월치만
확보돼 있다. 다른 업종에 반도체 숫자를 재사용하는 대신 `available: false`로 명시하고
국면 판정에서도 제외했다. 프런트는 이 지표를 차트 없는 회색 "미연동" 행으로 그린다.

연동하려면 업종별 시계열이 필요하고, 관세청 K-stat·KOSIS는 API 키가 있어야 한다. ECOS는
FinanceDataReader가 키 없이 붙는 비공식 엔드포인트를 쓰지만, 품목별 무역지수 항목코드를
따로 찾아야 해서 별도 작업으로 남겨둔다. 없는 데이터를 그럴듯하게 채우는 것이 이번 수정이
없애려는 문제였으므로 추정치는 넣지 않았다.

## 남은 한계

- 반도체 외 업종은 시세 기반 2개 지표로만 판정한다. 표본이 적어 국면이 상대적으로 민감하다.
- 업종 지수 바스켓은 동일가중이라 시가총액 비중을 반영하지 않는다.
- `SemiCycleDashboard`의 다른 탭(사이클 시계, CapEx 트래커, 서브섹터, ETF 매트릭스)은
  이번 범위가 아니라 그대로다.
